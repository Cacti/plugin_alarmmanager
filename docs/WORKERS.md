# Local workers

Requirements: PHP >=8.2 with OpenSSL, pcntl and posix; MariaDB >=10.11/InnoDB. Tests used PHP 8.3.6 and MariaDB 10.11.14. MySQL is not qualified and setup refuses it. HTTP needs cURL; email/scripts require /usr/bin/setsid. Run only in an isolated Cacti lab until producer integration and full deployment qualification are complete.

All database CLI entry points set Cacti conn_mode=offline before cli_check.php. They use the poller's local database and do not bootstrap a main-server database connection. The daemon (`alarmmanager_daemon.php`) opens no database connection; it spawns fresh PHP workers (`includes/worker.php`) and supervises them. Local HTTP delivery and separate-database credential provisioning have fixture coverage; a complete Cacti remote outage deployment and reconciliation remain unqualified.

From the installed plugins/alarmmanager directory, after Cacti plugin installation:

```sh
php cli/status.php
php alarmmanager_daemon.php
```

Normal Cacti plugin install/upgrade creates that poller's schema and random setup key; there is no separate local-setup command. Configuration must be provisioned to each local database (`php cli/remote.php --configure=/secure/routing.json`, or the full provisioning bundle in REMOTE_COLLECTORS.md). Encrypted credential save/backup/rotation/provisioning is described in CREDENTIALS.md. Disabled plugins pause worker claims. Source collector identity is distinct from local processing owner.

Administration → Daemon enables/disables daemon workers and sets the processing and delivery pool sizes (defaults: two and four). Install and start `service/alarmmanager.service` once, using the local web/PHP account so it can read the owner-private settings in Cacti’s `cache/alarmmanager/workers.json`. The controller stays in standby while disabled, publishes its status, and applies saved changes within a few seconds. Enabling requires a running controller. Disabling finishes current jobs and returns processing to the Cacti poller. Settings bound each pool to 64, processing minimum one; delivery may be zero. SIGTERM/SIGINT finish in-flight work within the shutdown budget, then forcibly terminate remaining children. Settings are reloaded automatically; SIGHUP also triggers a reload. Invalid reload keeps prior settings. Explicit `--config=/path/to/workers.json` remains available for manually managed deployments; legacy files without `enabled` start enabled and are separate from the administration controls. Crashed workers restart with bounded exponential backoff. Adapt paths, account and configuration in service/alarmmanager.service before installation; its stop budget includes the default grace period. This is the same single-daemon deployment shape as plugin_thold's `thold_daemon.service` — one service unit, the daemon owns every worker pool.

## Poller-integrated mode

Installations that prefer no resident service use the registered `poller_bottom` hook instead: at the tail of every Cacti poller cycle the plugin drains bounded processing and delivery work inline (`alarmmanager_poller_bottom()` in `includes/polling.php`). Each successful cycle writes `SYSTEM ALARMMANAGER STATS: Mode:poller Time:… Processing:… Delivery:…` to the Cacti log, including idle cycles with zero jobs. The drain budgets 500 jobs per role against a 60-second wall budget per role, which stays well inside the 300-second default poller interval; backlogs that regularly outgrow it belong on the resident daemon. The plugin-disabled state skips the drain, and each poller's drain heartbeats under one deterministic worker identity per role so the workers table accretes one row per role, not one per cycle. The queue lease/fencing makes interleaved claims with a running daemon safe, and the poller drain automatically pauses while the managed daemon is enabled.

A single systemd unit ships as `service/alarmmanager.service`; it runs the daemon, which spawns and supervises all worker pools itself — no separate worker units or timers are needed. `cli/status.php` prints the same local queue/worker metrics the Administration → Workers page renders (`alarmmanager_metrics()` in `includes/workers.php` is the single implementation for both).

Time budgets are checked between jobs; in-flight work can extend to its configured deadline. Claims take row locks with SKIP LOCKED, commit immediately and use random lease tokens. Processing waits behind earlier pending, leased or terminally failed jobs in its stream. A failed processing predecessor blocks only that stream and needs operator repair; no repair UI is implemented. Destination retries preserve stream order, but a terminal delivery failure does not prevent a later recovery. Priority ages to prevent starvation.

Endpoint row locks enforce concurrency and minimum start interval across workers sharing a local database. Limits are per local queue, not fleet-wide. Reapers bound work to 100 rows, reclaim expired leases and record abandoned attempts or terminal failures. Finalization checks both token and unexpired lease; stale workers cannot commit completion. Transient deadlock/lock-timeout transactions retry up to three times after rollback. Handler calls run outside transactions with a PCNTL deadline; phase-5 adapters must also configure native I/O deadlines. REST API, webhook, email and script handlers are registered. WebSocket remains unsupported and queued. Endpoints without a valid transport definition cannot send.

Status reports queue counts, oldest age, retries, recent completion, worker heartbeat, unsupported destinations and streams blocked behind failed processing. Errors are sanitized codes. Loopback fixtures exercise real HTTP/TLS/script delivery and the pinned Cacti mailer over SMTP. No production destination was contacted.
